## 做了什么，没证明什么

- 顺序运行ASR四组（INT8/FP32 × 非实时/实时）、LLM一组、TTS一组。6个配置退出0，22条正式输入均有完整记录，没有超时或内存保护触发。ASR的12次送音只来自3个固定材料，不是12条独立语料。
- ASR初筛3条为机器人指令、FLEURS普通话片段和静音；只有FLEURS带独立转写，所以CER覆盖每配置1条。英文专名、数字与汉字转写差异保留，不做额外数字等价处理。机器人录音只保留输出，不使用旧模型共识当正确答案。静音输出为空符合预期。
- LLM六条输入、输出、rubric及逐项判断见[文本评审](llm-review.json)。评审者是Codex助手的文本检查，没有独立人工或大规模评估；5/6不是通用准确率。JSON任务正确返回指定对象，没有中文句末标点，其首句等待为null，不当作失败。没有执行任何模型生成的机器人动作。
- TTS四条分别覆盖招呼、数字/温度、日期/时间、否定指令。WAV头、帧数与非零信号检查见[PCM完整性](tts-integrity.json)。输入文本是否正确读出尚未人工试听，没有MOS、自然度或发音合格结论。本机试听页位于 `/home/orangepi/.cache/edge-voice-v2/runs/2026-10-22-voice-screening-v2-r1/listening.html`，四段音频留在Git外。
- 不启动ROS、YOLO、麦克风、播放、回声消除或打断测试。不能相加单模块成绩推算共跑或完整交互等待。

## 等待与资源边界

CPU2线程是传给引擎的配置参数，不代表进程树只有2个线程；实际线程数、CPU核秒、频率和温度保留在资源日志。实时ASR推理窗占整机4核CPU容量约25.7%（INT8）/28.4%（FP32）；LLM约49.8%，TTS约48.9%。这是独立运行的阶段平均值，不是共跑总CPU预测。

资源每约200ms采样，PSS为进程树分摊内存的采样峰值。推理窗PSS峰值约116/156MiB（ASR实时）、559MiB（LLM）、378MiB（TTS）；全进程峰值与分阶段值分开保留。重复的inference窗口逐条保留并按时长加权，未被最后一条覆盖；每窗CPU包含sample_bracket或phase_interior_samples范围及缺失原因。

ASR计算RTF包括特征/解码/结果检查、reset、EOF及3.2s追加静音的计算时间，分母是原音频时长，不含送音等待或加载。实时模拟按**块起点**每100ms绝对时刻送块，区别于旧v1块末端约定，不直接与旧等待比较；首partial从第一块起计，含文件前导静音，不是人工开口后等待。

最终等待由原始final事件的**最后一个非空endpoint**重算，排除后续空端点和EOF强制结果；没有直接使用worker中可能指向后续空端点的旧final字段。INT8相对能量末端锚点的等待1.381–1.762s，FP32为1.422–1.800s；锚点是20ms RMS>-35dBFS，不是人工末音。文件自带尾静音可能使相对文件末尾等待为负，不裁成零，也不当异常。完整事件仍保留供核对。

LLM等待为请求到首非空content/首个。！？闭合短句。原生日志prompt处理约7.939–10.746s，对应40–54个prompt token，`cache_n=0`；这与TTFT接近，只能说明本轮等待构成，不证明库、硬件或量化的独立根因。输出decode传输观察速度中位数约3.881 token/s，与native timings字段分别保存。

TTS首PCM是整句generate返回后转为PCM16就绪，不包含写盘，不是真正流式首块，更不是扬声器出声。RTF是generate耗时/生成音频时长；当前四条合成都慢于音频播放时长。不得用这些数值直接推算整机对话延迟。

## 协议与证据

每个配置加载一次，首次请求与独立预热分别计时，预热不计正式样本；之后3秒待机，再执行固定用例。模型、库、输入身份与配置均沿用已冻结清单，运行前112文件检查通过。hash读取会预热文件缓存，不称冷盘启动。

实际执行逐模块上限600s，全部总上限1800s；ASR每子配置90s。LLM/TTS常驻进程的单输入截止90s、模块进程600s；Python信号对原生阻塞调用不能保证即时抢占，模块硬预算兜底。没有自动扩大候选、重跑或执行三轮复测。

`asr/`、`llm/`、`tts/`保留逐配置result/events/resources、请求与输出、stderr/stdout。输出WAV保存在外置cache，每个目录的external-media.json固定路径/hash。[measurement-source](measurement-source/report.py)保留执行器、worker、聚合与HTML源码快照；五项报告测试验证重复阶段窗口、缺失值、小样本统计、HTML转义及先解释指标再展示数据的顺序。

本轮结果使用`edge-voice-screening/1`、协议v2，是支持Python ASR/LLM/TTS的扩展报告；不冒充仅支持ASR C API v1的旧validator输出。沿用v1指标单位/范围/缺失原因语义，边界以本报告JSON中的metric_definitions为准。复现报告只读原始记录，不运行模型：

```bash
python3 -B measurement-source/report.py --render
```

`--render` 只读取 `results.json` 重新生成 HTML；不加此参数会从原始事件重新聚合 JSON。

推荐与rubric作为独立JSON输入，可在不修改原始测量的情况下复查。原始结果、参数、清单、模型身份和源码不得覆盖；后续优化另建实验。
