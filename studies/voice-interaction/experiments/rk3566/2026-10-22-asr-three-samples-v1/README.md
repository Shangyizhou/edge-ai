# ASR 三条有声材料：同模型精度与资源对照

日期：2026-10-22。用户要求每模块展示三个有内容的 benchmark 样例，输入与真实输出直接可见，结论包含速度、质量、CPU 与内存。展示只在临时草稿迭代，原 HTML 不改。

## 结论与范围

同款 zh14M CPU 混合 INT8、FP32 × 尽快送入、100ms 块起始实时送入，分别独立启动一次进程；每配置 3 段有声录音，共 12 条正式执行记录，只有 3 份独立材料，不是 12 份独立语料。四组均退出 0，无缺失输入。先首请求、独立预热、3 秒待机，再正式推理；与前轮保持参数和计时边界一致。

| 配置 | 三段计算RTF中位数 | 推理窗CPU/整机4核 | 推理窗峰值PSS |
| --- | --- | --- | --- |
| zh14m-int8-fast | 0.290 | 82.55% | 115.73 MiB |
| zh14m-int8-rt | 0.300 | 26.05% | 115.28 MiB |
| zh14m-fp32-fast | 0.373 | 81.20% | 158.87 MiB |
| zh14m-fp32-rt | 0.385 | 29.47% | 158.69 MiB |

机器人指令在本次四组中均转写为“机器人请让底盘上前移动二十厘米”。用户已对照上轮录音和两种精度转写确认正确；本次输出与确认文本一致。这个个人业务检查单独记录，不倒填为数据集独立参考。两段公开语音的 CER 两种精度、两种场景均为 30/66=45.45%，只覆盖该固定子集，不能推断总体准确率。旧报告的 20/37=54.1% 覆盖一条参考语音，保留原样，不把样本改变当成识别改善。

实时送入 INT8 的 PSS 约115MiB，FP32约159MiB。保留INT8候选及FP32质量对照，既看实际转写也看资源差异。公开语音仍有明显错误；命令成功不能替代广泛质量验证。

## 输入与测量证据

- `asr-fixtures.json`：原固定输入清单，正式使用 command、fleurs-1805-1、fleurs-1965-2；official0 仅作首请求及预热，其他未执行材料仍标明于配置。文件位置、SHA256 和参考来源保留；音频在 Git 外。
- `asr-screening.json`、`protocol.json`：本次冻结配置与范围；一次性预算600秒，单进程90秒，不自动扩展。
- `assets-manifest.json`、`runtime-manifest.json`：沿用准备资产和实际运行库身份。`manifest.json` 记录本次环境及文件身份，与前轮共同的35项资产/源码逐项一致。
- `asr/*/`：独立配置、事件、200ms资源采样、stdout/stderr、返回码、质量结果。`results.json` 为从这些记录派生的汇总。
- `measurement-source/`：从前轮冻结副本复用的测量代码及本轮执行脚本，不维护生产实现；不运行历史执行脚本覆盖旧数据。

CPU为推理窗进程树占整机4核容量的时长加权均值，PSS为窗口采样峰值。实际内存比例以本机MemTotal为分母；RTF计算含追加3.2秒补零计算、不含加载和实时送音等待。首字含文件开头静音，端点取最后非空endpoint相对能量结束锚点，EOF强制输出另留证据。线程参数不等于进程实际线程总数。
