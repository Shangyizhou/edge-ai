# 关键9工具与固定角色 LoRA 验证

本实验对应 [#11](https://github.com/Shangyizhou/edge-ai/issues/11)。输入是官方 Qwen3-0.6B c1899de、冻结的9工具目录和来源可核实的小沫角色事实。测量仅到原生调用的纯 JSON/Schema/Registry 接收，不执行设备操作。

数据为 assistant 构造的合成样本：300训练、60验证、120封存最终测试。训练中216工具（含12双调用）、66角色、18聊天；验证36工具（含9双调用）、18角色、6聊天；最终72工具、36角色、12聊天。分组先于样本实现：完整指令句式及参数变体不跨分区，角色使用直接提问/情境提问/断言纠正三个不同表达家族，聊天使用不同对话情境。各分区仍覆盖相同工具意图；不能将这种小规模模板数据称为真实用户分布或未见意图泛化。

`data/manifest.json` 固定数据版本、SHA256、分组和旧开发输入排除数；`data/persona-rubric.json` 在训练前冻结。最终集只保留外部地址和 `data/holdout-seal.json`，本工单没有运行或读取最终测试输出，配置选择只使用60验证。最终集在外部资产目录，与模型权重一样不在 Git。

角色审核者为 assistant GPT-6 Codex，无人工验收。审核须阅读完整回答，检查来源事实、遗漏、矛盾、未知背景与模型来源区分。自动关键词指标只作辅助，不代替完整语义审阅。创建者真实姓名、生日、年龄、出生地点、真实履历均未知；用户创造角色不能解释为用户研发了 Qwen 基座模型。

复现时使用外部锁定 MLX Python，调用 `python -m tools.qwen_lifecycle finetune REQUEST NEW_RUN`；所有完整样本都验证非思考模板、assistant loss mask、目标 Schema 与序列长度，拒绝截断。训练 seed42 同时设置 NumPy/MLX，rank8、最后8层q/v、梯度累积8，微步与optimizer updates分别记录。训练与验证仅使用精简system，评测再作未微调/LoRA × 完整/精简system的受控矩阵。

推理采用相同 MLX-LM/Metal/BF16基座、9工具、60验证输入、temperature0、max_tokens256、context8192、prefill512、每例新缓存；完整system沿用冻结基线文本，精简system为“你是机器人助手。需要操作时使用提供的工具，否则正常回复。”。完整system含一些本轮未提供的工具名，保持与已冻结基线一致；实际工具白名单仍由9个Schema控制。

资源口径：逐例进程树CPU占整机逻辑核容量、RSS和MLX峰值分配分别记录，二者不相加。主机swap和内存压力为整机状态，不能归因单个模型；采样器保留训练窗内主机swap变化，另有训练中快照；这些整机量不证明单进程因果。MLX prefill计时包含首模型token，decode计数可含EOS；训练target tokens/s不同于生成tokens/s。单轮n=60不能据此宣称稳定尾延迟。

## 证据入口

- [配对HTML](report.html)：60条输入、四组真实输出、逐条角色审核。
- [所有指标](inference.html)、[训练/导出阶段](stages.html)、[选定训练曲线](loss-selected.svg)。
- `source/`：实际采集器和数据生成器源码快照；`training/`、`validation/`、`export/`：不可改写的原始配置、事件、资源、日志与哈希。
- `persona-review.json`：逐条完整上下文审阅身份与理由；`selection.json`：基于验证行为的配置选择及动态输入边界。
- `evidence-manifest.json`：本实验仓库内证据文件身份。

浏览器file预览受策略限制，本轮不绕行其他浏览器/localhost；HTML只进行了静态引用、章节、CSS响应式检查，实际浏览器视觉尚未验证。

模型执行、验证集格式/角色结果、生产集成和完整交互验收分别成立。最终独立测试、板端最终候选、ROS共跑、硬件动作和产品质量均需后续独立验收。

精度细节：四组基座权重均BF16；LoRA可训练矩阵为FP32，原生MLX实现将增量cast回输入dtype后与基座输出相加。单独保留源码与adapter dtype证据，不能把adapter存储类型隐去或称四组全部张量均BF16。

## 覆盖与解释限制

- 封存最终120中的72工具样本均为单调用；多调用只在本轮训练/验证覆盖，不宣称最终独立多调用验收。原封存集不因本轮发现而改写，若后续增加独立多调用挑战须单独版本化。
- 普通聊天的自动通过仅表示有普通文本且无工具调用，不代表自然度/帮助性已人工验收。
- 完整与精简system的内容和长度同时变化，不能把效果差异单纯归因于token长度；完整system还有未提供工具的旧提示。后续动态工具Schema与执行保护始终独立生效。
- 数据生成源快照在真实生成后保留；维护模块随后仅格式化并新增CLI，原数据与测量不改写。修正数据的源码为 `source/t11_data_v2.py`，它只读取300训练及60验证，不读取封存最终集。

## 保留的验证驱动迭代

1. **v1 / 512微步**：原始300训练，64次更新。短system工具Schema34/36、精确29/36，角色完整审阅14/18；完整system角色7/18，出现“用户研发底层模型”的错误。短提示也曾虚构北京、2005年、博士后履历。见[原始配对输出](trial-v1-paired.html)、[角色审核](persona-review-v1.json)、[工具失败](trial-v1-tool-failures.json)。
2. **v2 / 768微步**：以42转义多调用+42未知背景替换84重复无参数样本，总300，174工具/108角色/18聊天。短system工具Schema36/36、精确35/36，角色完整审阅8/18；完整system工具精确35/36、角色7/18。更多未知样本解决了旧城市/任职编造，却干扰了已知名字、创建者和字段完整性。[配对输出](trial-v2-paired.html)。
3. **预先声明的负向短guard**：不提供小沫或科研角色，仅提示角色/基座区分和未知背景。相同guard下基座工具33/36、角色3/18；v2 adapter工具34/36、角色7/18，并出现姓名/创建者混淆和Qwen重复至截断。因此拒绝该guard，不能将其自动关键词13/18称为角色通过。[完整输出](trial-guard-paired.html)。
4. **v3 / 768微步**：保留42转义多调用替换，恢复42被未知样本挤出的工具样本，仍300，216工具/66角色/18聊天。将66角色目标统一为来源已核实的完整事实回答。这样所有角色问法学习同一个事实序列，减少六种回答路径互相串扰；验证数据和完整上下文审核标准保持原样。训练目标与原验证目标措辞不同，验证loss只是固定文本目标的似然，并非事实覆盖评分。

所有迭代只用验证结果诊断，未读取原封存最终120或根任务独立冻结的额外12多调用挑战。补充挑战由根任务维护，留给#14单独报告；本工作分支不载入该挑战。

## 选定候选与实际结论

选定 **v3 / 768微步 / 96次更新 adapter + 仅路由精简system**。system只规定设备操作/状态问题才调用工具、角色/姓名/创造者/背景问题用文字回答，没有提供“小沫”、科研角色、创造者、Qwen或未知背景事实。

| 同一60验证输入 | 工具原生 / JSON / Schema / Registry | 工具精确函数及参数 | 角色完整assistant审核 | 身份/聊天误工具调用 |
| --- | --- | --- | --- | --- |
| 未微调 / 原短system | 34 / 34 / 34 / 34（分母36） | 33/36 | 1/18 | 0/24 |
| v3 / 原短system | 36 / 36 / 36 / 36 | 32/36 | 17/18 | 1/24 |
| 未微调 / 完整system | 35 / 35 / 34 / 35 | 25/36 | 5/18 | 0/24 |
| v3 / 完整system | 36 / 36 / 35 / 36 | 31/36 | 9/18 | 5/24 |
| 未微调 / 仅路由短system | 0 / 0 / 0 / 0 | 0/36 | 0/18 | 0/24 |
| **v3 / 仅路由短system（选定）** | **36 / 36 / 36 / 36** | **33/36** | **18/18** | **0/24** |

这证明原短提示下固定事实保持从1/18升至17/18；不靠短提示携带事实。最后的路由提示只修复名字问题的误调用，并使选定条件达到18/18。相同路由提示会使未微调模型退化，不把这一较弱对照单独当作“基座能力”，也不把18/18小合成验证称为所有人设或真实用户质量通过。固定事实答复采用相同规范表达，未评审丰富自然对话风格。

选定条件仍有3条工具精确失败：`valid_022`将进入目标跟随错误选为disable_tracking；`valid_029`和`valid_032`遗漏歌曲名中的反斜杠。它们的原生/JSON/Schema均合法，说明格式通过不等于意图和参数复制正确。[完整失败证据](selected-tool-failures.json)。

同adapter完整→仅路由短system，prompt中位数2047→920 tokens，减少55.1%；prefill中位数0.606→0.223s，decode吞吐54.79→67.22tokens/s，逐例完整生成中位数0.975→0.531s。输出长度和内容也变化，且单轮主机状态不完全可控；不是纯提示长度或微调加速倍率。选定推理进程窗CPU6.14%/10逻辑核、采样峰RSS400.84MiB、MLX峰值分配1633.27MiB，二者不相加；没有GPU利用率测量。

v3实际训练621.60s（训练阶段619.50s），327,680可训练参数，最大完整样本950tokens/2048容量；MLX峰值分配2,796,992,886bytes。训练loss末次0.001、验证loss末次0.802；虽然验证loss比v2的0.064高，完整事实审核更好，因而选v3而不选最低loss。

合并2.756s、转换F16 9.953s、Q4_K_M量化9.081s，准确阶段资源、退出码、bytes和SHA见[导出原始结果](export/results.json)。高精度merged目录1,203,585,805bytes，F16 GGUF1,198,182,336bytes，Q4_K_M396,704,704bytes。base→merged体积下降主要涉及tied权重去重与序列化，不是LoRA压缩倍率。这里只确认制品转换完成，合并/转换/量化后真实推理与精度对照交给#13，不把转换成功当作推理接受。

模型和所有adapter/checkpoint保留Git外，谱系见`export/results.json`；选定tensor `adapters.safetensors`与768步checkpoint同hash，其余checkpoint未删除。动态工具目录、Schema、权限、设备状态、会话输入与工具回执仍需运行时提供。未读取原120或根任务另外冻结的12多调用最终挑战；最终回归交给#14。

可复现接口与检查：新数据生成器 `python -m tools.qwen_lifecycle.datasets --help`；v2/v3修正脚本保存在source，不能覆盖原目录。`controlled-comparison-audit.json`核验14轮输入、工具、基座精度和生成配置；`skill-handoff-checks.json`核验3次训练、14轮真实benchmark和1次export，共18个技能handoff。15个项目边界/数据隔离/配对测试通过，维护模块ruff通过。所有1850余项证据见manifest，浏览器视觉仍未验证。
