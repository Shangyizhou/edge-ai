# 语音交互模型调研与性能测试

更新时间：2026-10-21。当前设备：Orange Pi 3B / RK3566 / 4GB。

## 为什么做

为机器人选择一套能在目标板上实际部署的本地中文语音交互方案：听到用户说话，识别成文字，交给本地LLM理解和回应，再合成为语音，播报后继续监听。同时确认它与已有视觉任务共享CPU、NPU和内存时的表现。

本主题为选型、提速和后续机器人接入提供可复测依据。每一步都要回答“能否运行、体验花在哪里、资源是否够用、还缺什么证据”，并保留参数、原始输出、失败及结论。

## 最终要交付什么

| 交付物 | 要回答的问题 | 当前状态 |
| --- | --- | --- |
| 方案与配置建议 | ASR、LLM、TTS各选什么模型、后端、精度和参数，为什么这样选 | 有候选与实测依据，完整组合尚未定案 |
| 可复现部署 | 固定模型来源/hash、依赖版本、运行配置，能在目标板复现 | 各模块已有部署记录；ASR生产ROS节点NPU路径已验证 |
| 完整交互性能报告 | 说完到识别完成、到首段语音、到播报结束和恢复监听分别多久 | 已测模块与ASR链路；整链路未验收 |
| 共跑与资源边界 | 与YOLO共跑是否掉帧，CPU/内存是否够，哪些计算应错开或重叠 | 已有短时共跑；完整交互组合待测 |
| 质量与适用范围 | 哪些中文指令、说话条件和对话长度可用，哪些情况失败 | 少量固定样本，无代表性准确率或长期稳定性结论 |

ASR要求实际验证NPU路径，优先沿用成熟目标产物；当前TTS和Qwen使用CPU。视觉目标已明确为上游缩放后的640×352、30fps。尚未约定整段交互的硬性延迟、内存或准确率门槛，不能自行把“十秒内”等数字当作已批准验收标准。

## 当前方法整理

当前按已确认的[轻量评测SOP](../../docs/methodology/model-evaluation-sop.md)：资源/性能为主、少量固定语料、ASR先验证、历史结果按口径转换。无需新建大规模语料或人工末音标注流程。已完成[ASR v1试点](experiments/rk3566/2026-10-21-asr-lite-v1/results.md)：6条约38秒素材、CPU/NPU共享适配器、4组筛选和12组三轮复测，输出JSON与静态HTML；另将60条历史记录转换为只读视图。下表保留既有研究阶段及整链路最终目标。

## 阶段如何往下推进

下面是按问题和交付物对已有工作重新归纳的阶段，不代表原实验按此编号执行。阶段完成只表示对应范围已有证据，不代表整体语音交互已完成。

| 阶段 | 这一阶段解决什么 | 做了什么、得到什么 | 状态及下一步依据 |
| --- | --- | --- | --- |
| 1. 路线与资产跑通 | 现有模型能否在RK3566运行，NPU是否真可用 | 核对旧Zipformer、SummerTTS、微调Qwen资产；跑通CPU基线及ASR历史RKNN模型/私有runtime2.2.0组合 | **已完成限定范围**；具备做实际参数比较的基础 |
| 2. 单模块性能对照 | 哪些模型和参数值得保留 | 测线程、TTS候选、Qwen同源量化及运行参数；记录RTF、TTFT、吞吐、PSS和失败 | **已完成首轮短测**；得到候选，尚未通过质量评估确定整套推荐配置 |
| 3. 共享资源与视觉共跑 | 单独能跑，放在一起是否仍能工作 | ASR驻留下LLM/TTS重叠对照；YOLO CPU候选/NPU、实际ROS节点及活跃ASR共跑 | **已完成短时回放**；发现计算竞争，不能只用单模块数值推算交互体验 |
| 4. 常驻流式ASR优化 | 如何避免录完再启动推理，端点调小是否有收益 | 常驻模型、实时PCM回放、1.2/0.8/0.6秒端点扫描、连续六轮及YOLO共跑 | **已完成探针验证**；保留1.2秒作为接入起点，并记录连续流文字变化 |
| 5. ASR生产节点接入 | 探针结果能否迁入真实ROS音频/控制接口 | 为已有C++常驻节点接入显式RKNN；验证新流、暂停、缺帧失败、恢复、关闭及实际YOLO共跑 | **已完成ASR单节点验证**；可以推进已有整链路组装的测量，尚未验收完整四进程 |
| 6. 整链路测量与瓶颈收敛 | ASR接入后，用户真正等待的时间由谁决定 | 下一步分解ASR final→LLM首段文字→TTS首段PCM→播放→新流恢复，并据此优化LLM输入、TTS分句和调度 | **待推进真实组合验收**；单模块已测不等于该阶段完成 |
| 7. 质量、稳定性与选型收尾 | 能否持续可靠使用，最终推荐什么 | 独立转写/EOS样本、多说话人和噪声、长会话、资源/失败恢复复测，再确定推荐组合及适用范围 | **待开展**；产出最终选型结论，而非只报告能运行 |

推进细节、每阶段的证据和下一步完成条件见[推进计划](roadmap.md)。

## 现在站在哪里

**已经从“模型能运行”推进到“生产ROS ASR节点的NPU接入可用”，但尚未证明完整本地语音交互达到可交付体验。** ASR进展领先于LLM/TTS整链路优化；不能把ASR完成比例当作整个主题的完成比例。

- **ASR：** 六次独立新流及一次错误后恢复的命令文本与既有参考一致；生产节点等待约1.57–1.71秒，计时相对固定能量末端，非人工末音。连续流六轮后段仍有文字变化。
- **端点：** 0.8秒未明显提速；0.6秒更快，但会拆开“机器人”和后续指令，所以未作为默认值。
- **LLM：** 已有同源量化、参数与短提示数据；更小量化并未自动更快。短提示结果不代表真实完整工具目录和长历史的等待。
- **TTS：** 已比较Summer及非小雅候选的CPU性能；分句首段就绪、实际首声和与LLM重叠后的收益尚未完成整链路验证。没有确认可直接部署的成熟RK3566中文NPU TTS产物。
- **共跑：** 生产ASR与实际ROS YOLO在640×352@30fps的45秒回放中完成1350/1350帧、零丢帧，检测延迟样本p95约40ms；不代表真实摄像头和长时间运行结果。

本仓库最近的实测没有启动完整Agent、麦克风、扬声器或执行识别文本中的机器人动作。ROS生产实现位于ros-robot本地交付分支；本仓库保存研究、复测工具和证据。

当前资源基线：实时回放三轮中位数，CPU/NPU占整机CPU容量约28.96%/4.79%，推理峰值PSS约128.39/215.34MiB（实际RAM的3.27%/5.49%），计算RTF约0.391/0.400。两者为不同精度的部署方案对照。NPU优先作为释放CPU的试验默认，质量仍限定于实际小样本，完整应用选型尚未完成。具体范围见下列ASR v1报告。
