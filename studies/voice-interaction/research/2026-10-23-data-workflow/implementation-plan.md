# Edge AI Skill 工作流适配与真实验证计划

日期：2026-10-23。状态：用户随后明确授权执行，已完成本轮有界技术验证。原计划的候选配置在实际运行提案中具体化；验证证据见文末，不将模型质量未达标写成产品验收。

依据：[部署边界调研](../2026-10-23-deployment-skill-boundaries/README.md)、[数据准备调研](README.md)。目标是保留现有六个 Skill，以明确交付和两类真实任务验证可组合性，不建立强制全链路执行器。

## 1. 完成后用户会怎样使用

1. Selection 明确候选、设备、模型任务和想比较的问题；已有候选可以跳过。
2. Benchmark 的评测准备模式确定任务方案、数据用途、评分规则和测量边界；不执行模型。
3. Prepare 按候选与方案准备实际推理环境、运行入口和最小真实推理；可复用已有环境。
4. Benchmark 在诊断/开发数据上测原始模型，Ask 解释是否需要训练、量化、改 prompt 或停止。
5. 确有需要时，Train 的数据准备模式制作 train/validation，并与评测侧核验分组隔离；交付数据报告后可以停止。
6. 在已确定的数据/参数/预算内开展小步训练，按验证表现选择 adapter；不根据最终集修改模型。
7. Export 按明确目标合并、转换或量化；Prepare 只重查受影响的候选与运行条件。
8. Benchmark 进行开发回归；候选与配置选定、冻结后，按预先确定的矩阵开展最终独立测评。
9. 结果进入 Ask/Selection 的选择记录，或停在当前阶段。实际机器人集成和共跑验收另计。

数据规划早于大量训练数据制作。Prepare 不作为数据设计的前置条件。Train/Export 各自负责自身执行环境，不将 Prepare 扩张为万能安装器。

## 2. 各 Skill 的具体改动

| Skill | 要补充的行为 | 明确不承担 |
| --- | --- | --- |
| edge-ai-ask | 区分建议、数据准备、开发诊断、最终测评；按证据引用路由，显示跳过原因 | 自动推进/调参循环、读取最终题目给训练出题 |
| edge-ai-selection | 输出业务目标、候选组合、待验证问题和初步测试建议；展示输入与执行输入分开 | 临时定义第二套评分真值；要求每轮重新选型 |
| edge-ai-prepare | 消费任务方案，检查资产/运行库/后端/运行入口，完成最小真实推理，将路径和采集条件落实为可执行配置；支持复用和局部重查 | 训练/导出环境总管，标签和划分政策，整体质量达标结论 |
| edge-ai-train | 增加“只准备数据”的模式：来源、分组、清洗、标注/生成、train/validation 导出与预检；训练执行只消费冻结版本 | 将最终测试案例用于制作训练资料；数据准备后自动训练 |
| edge-ai-export | 保持转换职责；产物交接携带源制品、格式、精度和受影响的就绪检查项；环境由自身管理 | 因转换退出0就宣称模型可用或质量通过 |
| edge-ai-benchmark | 增加“只准备评测”的模式；通用实验骨架＋任务方案＋执行适配器；支持开发/最终用途，预检、固定配置、评分、独立结果HTML | 把所有任务压成工具调用字段；边运行边改变题目、评分或条件 |

Skill 短入口只说明职责、模式与边界；细节放对应 references，确定性工作放 scripts。任务方案作为参考和配置，不为 ASR/Qwen/一页 HTML 新建 Skill。名称和数量保持当前六个。

## 4. 任务方案与适配器的最小切分

通用部分负责配置身份、数据引用、过程事件、超时、资源采样、失败保留和结果汇总；任务方案负责“测什么、怎样评分”；适配器负责“怎样调用这个模型/框架”。

第一轮只承诺两种具体任务，不泛称支持所有模型：

- Qwen原生工具/角色/聊天：复用 tools/qwen_lifecycle 现有协议和MLX/llama-http适配。分开统计原生、JSON、Schema、Registry、意图参数、人设/误调用；无调用分母不套用动作JSON。
- ASR转写：复用现有 voice/asr 执行与测量来源，经任务适配连接通用交付。CER使用有独立参考的子集；用户后验确认的业务文本单列；实时送入与尽快送入不得混成同一口径。

通用层不默认token/s。模型tokenizer不同时可记录各自吞吐，但不据此单独排名任务速度。所有任务记录设备、实际后端、进程/资源口径。Mac RSS和MLX分配不相加；Linux PSS/RSS分开；加载、冷首次、预热后与稳态分窗。

## 5. 数据阶段的实施顺序

定义行为/评分 → 收集来源与种子 → 初步检查/去重/识别来源和近重复族 → 按组分配用途 → 分别制作/扩充/标注 → 导出与模板预检 → 跨集合复核 → 审阅冻结。

同源改写保留parent_id并继承用途；不得先批量扩写再随机拆行。group_id不简单等于工具名，否则会意外变成未知工具泛化实验。重复审计可用独立检查器访问各集合，不能把最终题目全文反馈给训练生成器。

Train允许真实材料、人工案例、AI辅助混合制作，须记录生成模型/提示/脚本与复核。工具/单位/事实来自当前Registry/来源，不能采用讨论中假设接口当真实标签。训练数据使用匹配模板和原生tool_calls，完整样本长度、末尾assistant目标、非思考模式与监督mask均预检；Schema合法与语义正确分开。

训练/验证/诊断/最终是四种用途，不强制四套独立重复文件。最终材料提前隔离，最终候选与评分冻结在查看最终结果前。已观察Qwen最终132例只保留历史/回归身份。

## 8. 真实验证：区分四个层次

### V0. 只读回放已有真实记录

输入：

- Qwen：experiments/mac/2026-10-22-qwen-selected9-adaptation-v1 的 data/manifest、工具/角色标准、训练preflight/结果、selection和export结果；最终132例只用已公开汇总确认其历史身份。
- ASR：experiments/rk3566/2026-10-22-asr-three-samples-v1 的 fixtures/protocol/assets/runtime、四组原始记录和measurement-source。
- 已批准的Train/Export页面与当前Skill请求/结果合同。

操作：旧记录前后哈希核对；建立新目录下的交接映射与缺口清单；只读重算派生统计并渲染页面。Qwen还原300训练/60验证的历史口径，不把某次改写前数据与v3最终训练数据混用；原120和后来12例来源分别记录。ASR核对3份独立材料、4配置12次执行，而不是12份独立语料；CER仅相应独立参考子集。

通过：字段来源可追踪、旧数据未改、统计与原定义一致、缺失明确、两个任务未共享错误评分。该层只证明合同/报告回放，不证明新执行器能跑。

### V1. 数据阶段与故障路径，不执行模型

用新的明确标为演示的数据验证：同源改写跨用途时拒绝或标阻塞；缺少真实工具定义、错误参数类型、未知事实标签、过长序列、评分器缺失、旧就绪证据失配分别有明确结果；不自动修正后悄悄继续。

训练/评测准备模式生成新版本和审阅页后停止。审计生成器不得读取最终内容；通过输入清单、实际访问追踪/隔离测试检查，而不是只相信配置声明。验证最终题目不进入训练导出和报告；共享上下文限制如实记录。用已固定模型/tokenizer做模板渲染预检可加载tokenizer，但不能启动训练或生成推理。

通过：结果可重复、交接可直接消费、审批/未决标签显式、未开启训练/转换/模型服务、失败仍有报告。此层使用演示数据，不能计入真实模型准确率。

### V2. 新Qwen Mac小闭环，真实执行

目的：证明新工作流真实跑通，不要求小步LoRA一定改善能力，不以试点分数宣传泛化。

候选：复用官方Qwen3-0.6B及已验证Mac框架；当前工具Schema和角色事实作为明确输入，不改生产仓库。新建外置数据/运行目录，旧模型和实验只读。

建议小规模预算，实施前由覆盖方案和资源检查确定：train约60、validation约18、诊断约24、最终预留约24；数字不是比例要求，不足覆盖时应缩小试点承诺或另行调整预算。所有内容新制作、按来源组隔离，真实/合成明确标识，不从已观察最终例改写。先展示少量开发标签与评分自检，最终内容保持预留。此数据阶段之后可停止。

执行顺序：

1. 完成任务/数据版本审阅、划分审计、训练框架预检，保存基座与模板身份。
2. Prepare复用已有环境，最小真实推理，记录就绪；基座诊断24请求，确认采样和评分能工作。
3. Ask形成是否训练的建议。正常路径若无需训练就结束该分支；若要验证训练技术链路，则明确它是有界可行性试跑，不能假装业务必需。
4. 如训练已获执行授权：建议32微步、累积8作为形状验证候选，即约4次优化器更新；rank/层/学习率沿用经框架检查的候选并先解释。上限建议训练10分钟，达到预算或内存/系统压力异常立即停止，不自动扩大步数。保护条件的具体数值需在实测前根据环境形成配置。
5. 用validation的loss与任务表现记录选择或拒绝adapter；即使拒绝，也可在明确“技术验证”标签下检查导出路径，不能晋升为主候选。
6. 如导出已授权：使用新路径合并、转换F16、量化Q4；Prepare只更新新制品与必要冒烟，不重复下载基座和重装运行库。
7. 相同冻结诊断题比较基座/adapter及必要的导出前后版本。转换对照先比较非量化路径，避免将框架转换与量化变化混为同一因素；只在目标明确的比较上扩大矩阵。
8. 确定候选、prompt、解码和评分后才运行新的预留最终集；若适配仍有关键问题，可停在诊断，不强行开启最终集。配对矩阵提前声明；不根据最终分数再挑选参数。
9. 输出数据审阅、就绪、训练、导出、测评、决策记录，所有原始请求/输出保留。Mac推理试点建议单请求、每例最多128输出token、请求90秒上限、单阶段10分钟上限；若不能覆盖必要输出，应在执行前调整并记录，不能运行中静默截断当成功。

通过：新真实请求、进程采样、评分、训练/导出证据与谱系一致；每种失败可追溯且分母保留；真实质量未达标时仍如实标识。过程跑通与模型能力达标分别验收。实际CLI使用项目公开入口（当前有 python -m tools.qwen_lifecycle benchmark/finetune/export），新增数据准备/通用计划命令待实现后先打印dry-run，不把本计划中的概念入口冒充现有命令。

### V3. 香橙派两任务验证

执行前仅在被授权的阶段使用 ssh orangepi-ts；先检查实际设备、内存、磁盘、现有进程和依赖。ros-robot在 ~/code/ros-robot，只读取得所需协议；不修改/启动旧C++节点，不执行工具。不停止其他任务的模型服务，不覆盖既有模型，不为腾空间自动删除文件。

Qwen：新试点Q4与固定基座Q4在相同llama.cpp/CPU、上下文/KV/缓存/线程和新诊断子集对比，建议每候选12请求共24次，至少覆盖单调用、多调用/转义、无调用与角色问答；原始9工具保持来源身份，不承诺12例代表全部质量。记录首内容、完整有效调用、CPU与PSS，冷首次和热态分开。预算建议20分钟；新进程、独立端口、仅清理本轮进程。

ASR：复用原有3份有声材料，混合INT8/FP32各一轮，先固定100ms实时送入，共6次正式执行；首请求/预热单独记录。数据已观察，只验证协议与执行复用，不称新独立准确率。每进程90秒、阶段600秒为预算候选，记录实际转写/参考来源、CER有效子集、RTF精确边界、CPU/PSS。复用实际执行模块写薄适配层，不直接运行会覆盖旧目录的历史脚本。

## 9. 测试、报告与停止条件
