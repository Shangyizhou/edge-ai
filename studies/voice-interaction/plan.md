# 准备：目标、候选与怎样测

[首页](README.md) → 准备 → [单模型对比](models.md) → [机器人验证](integration.md)

## 我们要做成什么

在RK3566机器人上运行离线ASR、本地LLM和TTS，回复后恢复监听，并确认它们和YOLO一起运行时资源是否够用。

优先关注CPU、内存和等待，保留少量固定质量检查。复用官方材料、公开转写及现有机器人样本，不建设大规模语料，不要求新人工转写或人工末音标注。

**还没确定：** 完整交互的硬性等待、内存和质量门槛。这些需要在应用验收前明确，不能自行把某个秒数当成用户要求。

## 设备与已有条件

| 项目 | 已知条件 | 选择方案时要注意 |
| --- | --- | --- |
| 板卡 | Orange Pi 3B / RK3566 / 标称4GB | 内存占比按实际MemTotal计算 |
| CPU | 已运行ASR、Qwen和TTS候选 | 多任务会竞争，需单测后再共跑 |
| NPU | 历史FP16 ASR配合私有runtime2.2.0可用 | 不代表所有模型或新版库都可用 |
| 视觉输入 | 上游缩放后的640×352，目标30fps | 缩放、摄像头采集与检测推理分清边界 |

完整设备、驱动、运行库及资产身份保留在[RK3566部署说明](platforms/rk3566/README.md)和各轮manifest中；实际执行以该轮冻结环境为准。

| 任务 | 候选方向 | 下一步要回答什么 |

## 怎样测才值得比较

| 项目 | 首版做法 |
| --- | --- |
| 输入 | ASR已固定6条、约38秒小集；公开转写与模型共识分开 |
| 快速筛选 | 固定小子集，每配置1轮，先排除不能运行或明显不合适的候选 |
| 候选复测 | 仅入围配置独立3轮，保留每轮结果，报告中位数和范围 |
| 速度与等待 | 非实时供音测计算RTF；100ms块实时供音测交付等待，分别展示 |
| 资源 | 分加载、常驻待机、推理窗口，测进程树PSS与占整机CPU容量 |
| 质量 | 有可靠参考才算CER；无参考保留原文，不能宣称准确率达标 |

RTF是计算时间与音频时长之比，越小通常计算越快；它不是说完到最终结果的等待。PSS是进程树分摊的主机驻留内存，不是NPU独占内存。没有可靠NPU利用率、独占内存或功耗接口就记未测。

**两类比较分开：** 同源同精度、相同输入处理的组用于研究后端收益，且要核对实际执行；不同精度或模型的组用于选择现实部署方案，不能称为纯硬件加速倍率。优化后重新检查输出，质量明显退化的方案不进入性能复测。

## 怎样沿SOP推进

| 日常工作环节 | 对应正式SOP | 何时继续 |
| --- | --- | --- |
| 准备 | 1研究问题、2环境档案、3候选调研、4冻结协议 | 目标、候选身份和比较条件清楚 |
| 单模型测试与选择 | 5快速筛选、6候选复测 | 有可用候选、重复结果和有限质量证据 |
| 机器人组合验证 | 7共跑与应用 | 组合资源、完整时间线及失败恢复有实际证据 |

筛选、复测和优化复验是一个循环；各模型、各候选分别记录状态。已有后续实验继续保留，但不能替前面的证据缺口补勾。量化无需成为每个模型必经步骤。

统一指标与数据规则以[轻量SOP](../../docs/methodology/model-evaluation-sop.md)和[结果格式](../../docs/methodology/result-format.md)为准，执行方法见[工具说明](../../tools/edge_benchmark/README.md)。每轮冻结输入、参数、预算与环境后生成JSON和静态HTML；超过预算保留事实，不无限扩矩阵。
