# 机器人验证：放在一起是否仍然可用

[首页](README.md) → [准备](plan.md) → [单模型对比](models.md) → 机器人验证

**ASR节点及短时视觉共跑已有证据，完整本地语音交互尚未验收。** 这里把共跑、生产接口和完整体验分开看。

## 已经验证到哪里

| 范围 | 实际做了什么 | 目前能判断什么 |
| --- | --- | --- |
| 三模块竞争 | ASR驻留，LLM/TTS重叠测试；Summer同句RTF由0.803升至1.571 | 并行会拖慢任务，不能把单模块成绩相加。[记录](experiments/rk3566/2026-10-21-baseline/results.md) |
| 流式ASR | 常驻、实时供音、端点扫描及连续六轮 | 可进入节点验证；连续流后段文字变化仍待定位。[记录](experiments/rk3566/2026-10-21-streaming-asr/results.md) |
| ROS ASR节点 | 六次新流、暂停、缺帧失败后恢复和关闭；命令文字与既有参考一致 | ASR单节点接口可用，不等于整套交互完成。[记录](experiments/rk3566/2026-10-21-ros-asr/results.md) |
| ASR + 实际ROS YOLO | 上游缩放后640×352@30fps，45秒回放完成1350/1350帧；检测延迟样本p95约40ms | 该短回放无丢帧，不能外推真实摄像头或长期稳定性。[记录](experiments/rk3566/2026-10-21-ros-asr/results.md) |

ROS ASR固定回放中的交付等待约1.57–1.71秒，相对能量末端计时，非人工末音延迟。接口/Launch回归30项通过，其中故障契约有C ABI替身测试，与真实识别证据分开。真实RKNN调用中途硬取消没有保证。

实际YOLO后端、CPU候选和不同共跑口径见[视觉实验](../object-detection/experiments/rk3566/2026-10-21-yolo/results.md)；CPU候选权重身份不能严格对应部署RKNN，不能据此报告纯硬件加速。

## 尚未验证什么

完整Agent、真实麦克风、扬声器和四进程组合尚未完成真实体验验收。最近这些实验没有执行识别文字中的机器人动作。已有软件组装或替身测试不能代替真实模型整链路测量。

生产实现仍在ros-robot仓库维护；本仓库的记录不等于该生产分支已远端发布。具体实现提交、分支和配置见ROS实验报告。

## 后续按什么顺序做

先完成[单模型对比](models.md)中的关键缺口，再固定一套组合，按以下顺序测量：

1. **建立完整时间线。** ASR最终文字 → LLM首个可用回复片段 → TTS首段PCM → 播放开始/结束 → 恢复监听。先用已有录音做受控回放；模拟播放和真实声卡分开，未播放不称首声。
2. **找到最大等待再优化。** 核查LLM真实system/工具/历史输入；比较TTS整句与分句、常驻及重叠调度。优化前后保持输入与计时边界一致。
3. **检查回合交接。** ASR结束后暂停输入，播报完成恢复新流；旧流和迟到事件不能串入新回合，保留失败与恢复证据。
4. **再加入视觉。** 使用相同组合和30fps目标，比较独跑与共跑，记录积压、丢帧、CPU和PSS。

## 怎样才算完成

有固定组合的真实模型时间线、资源数据、有限质量与异常恢复记录，能解释主要瓶颈并给出适用范围。完整交互预算还需约定；当前不承诺硬性秒数。

质量检查保持个人开发者可承担的规模：公开转写、少量机器人样本、LLM任务与协议检查、TTS数字/日期试听。多说话人、噪声和长会话可按需扩展，未测范围明确保留，不由小样本推断长期可靠。
