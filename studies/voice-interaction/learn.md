# 看懂当前模型与测试

机器人语音交互包括：ASR把录音转为文字，LLM理解并生成回答或工具调用，TTS把回复合成为音频。能分别运行不等于整套交互已经通过。

| 指标 | 含义 | 判断边界 |
| --- | --- | --- |
| ASR计算RTF | 计算耗时÷输入音频时长，越低越快 | 不含加载和实时送音等待；补尾部计算范围见实际协议 |
| CER字错误率 | 字符编辑错误÷参考字符数 | 只覆盖有独立参考的材料；同时看录音与实际转写 |
| 首内容 / 首句等待 | 请求到首个文本片段 / 完整闭合句 | 两者不同，也都不等于最终播放等待 |
| TTS首PCM / RTF | 本轮是整句音频就绪；合成时间÷输出音频时长 | WAV有效不代表发音正确，需试听 |
| CPU容量占比 | 被测进程树占整机4核的平均容量 | 不是整机所有进程的总负载 |
| PSS / RAM占比 | 共享驻留内存按比例分摊；相对实际MemTotal | 是采样峰值，不是内核绝对高水位或整机内存 |

SFT用正确输入输出样例适配业务，LoRA减少需要更新的参数；二者不同于INT8/Q4等部署量化。工具调用的格式、参数与用户意图需分别检查；通过Schema校验仍可能违背“不要执行”的意图。
