# 端侧模型轻量评测SOP

版本：v1.1（补充同精度主对照要求）。确认日期：2026-10-21（Asia/Shanghai）。状态：用户已整体确认，按此实施；实际工具支持范围与验证结果另行记录。

## 目的与约束

为个人开发者选择实际可部署的端侧模型组合，以资源占用和性能为重点，用少量固定样本检查基本功能和质量。首个试点为RK3566 ASR，后续扩展到TTS、LLM与视觉任务。

优先复用成熟模型、框架、后端与随附测试材料；已有参考文本直接使用并记录来源。机器人业务补少量现有样本即可。首版不建设大规模语料，不要求新录音、人工逐字转写或人工末音标注，不引入训练/自研模型转换作为前置工作。

小样本只支持其覆盖范围内的判断。质量是最终推荐的依据之一，资源与速度不会自动替代识别质量；没有可靠参考时，可给出性能候选及待验证项，不声称完成质量选型。

## 一、研究流程

| 阶段 | 工作 | 产物/推进条件 |
| --- | --- | --- |
| 1. 研究问题 | 明确用途、目标设备、关注的资源和性能，以及已知约束 | 研究范围及待回答问题 |
| 2. 环境档案 | 核对CPU、NPU、实际总内存、OS、驱动、库、频率/温度状态和后台负载 | 带来源的设备与环境身份；理论能力和实际可用能力分开 |
| 3. 候选调研 | 记录模型来源/hash、精度/量化、框架、后端、预后处理及可用参数 | 候选部署组合；不能运行的保留排除原因 |
| 4. 冻结协议 | 固定少量用例、来源和参考、输入方式、指标定义、预热/重复/超时与版本 | 同一比较组保持这些条件，变更后另建版本/组 |
| 5. 单模块筛选 | 仅运行本实验模型负载，各配置1轮小样本 | 执行状态、输出及资源/性能事实；选择需要复测的候选 |
| 6. 候选复测 | 入围配置独立执行3轮，保留每轮、每用例数据 | 报告中位数/范围、参考质量及局限；默认推荐一套，必要时保留少量备选 |
| 7. 共跑与应用 | 基线确定后，再测多个进程同场负载及实际应用链路 | 相对同条件基线的退化、资源竞争和实际交付时间 |

每次执行先生成结构化数据，再生成静态HTML。候选数量、样本总时长和整轮预算写入配置；超过预算保存已完成事实，不自动扩矩阵或长测。

共跑不以单模块成绩相加推算。共跑或应用结果不适合时，可返回候选复测调整方案。

## 二、比较与复用

CPU/NPU后端收益研究应先建立**同源权重、同精度、相同输入与流式配置的受控主对照**，再补不同精度的实际部署方案。不能因为已有两套资产更方便，就用混合精度比较替代主基线或据此给出后端默认推荐。

精度需核对权重表示、输入输出和实际算子执行；CPU将FP16转回FP32、混合精度或后端回退必须披露，不能只凭文件后缀或一项precision声明认定相同。若尚无可运行的匹配组合，记录受控基线未完成及具体缺口；现成方案数据可保留为补充，不宣称已回答同精度后端收益。

- **受控后端对照：** 声明并核对权重、精度、输入、预后处理等保持一致的条件；硬件加速归因只覆盖实际受控部分。
- **部署方案对照：** 比较现实可用组合的资源、性能和输出；允许模型/精度/框架不同，差异全部可见，不称纯硬件加速倍率。
- 输入与任务要求可复用，CPU/NPU由适配器执行；每套部署配置保留独立执行结果。兼容性依据协议和比较条件，不依据“文件名相同”猜测。
- 进程启动、模型构造、首请求和预热后请求分别记录；未经受控验证不称冷盘启动。
- 非实时吞吐、实时流式、ROS消息链路分别统计和展示。

## 三、ASR首版用例与方法

### 用例小而固定

建议首版总计约6–10条短素材、总时长约1分钟，实际文件清单和时长以可取得资产为准。初筛使用其中固定小子集，复测使用完整小集。数量是低成本试点起点，不是统计充分性门槛。

| 材料 | 使用方式 |
| --- | --- |
| 官方/模型随附示例 | 优先复用，适合验证能否运行和性能；附带参考文本时注明是语料转写还是示例输出 |
| 有参考文本的公开小样本 | 必要时补少量，固定版本、ID和hash，不默认下载完整大型语料；仅计算固定子集上的质量 |
| 项目业务样本 | 少量现有机器人指令/问答、数字等；无独立参考时保留识别原文，作流程与一致性回归 |
| 静音/停顿/拼接等派生素材 | 按需覆盖行为边界，注明派生关系；不当作新增独立说话人或质量样本 |

合成语音需标明来源，不替代真人场景证明。优先保留原文件；必要的重采样、声道或文本归一规则固定版本，CPU/NPU使用相同派生产物。

### 两种测法

1. **非实时吞吐：** 不按真实语音节奏等待，测计算RTF与资源开销。
2. **实时流式：** 按固定音频块和绝对到达时间回放，测首个partial、最终结果交付、提交滞后和资源。落后时保留事实，不通过重设时间起点掩盖积压。

首版复用已验证的100ms送音机制；固定尾静音及其计时/分母规则。独立素材新建stream；连续/端点reset行为另列用例。模型只在进程级加载，首请求、独立预热流及预热后测量分别标记。每轮独立启动进程，加载缓存状态如实记录，不清理全机缓存。

CPU常驻分支已通过实际运行；仍须补齐匹配精度资产与执行核验，才能形成同适配器CPU/NPU受控主对照。已有CPU Python/CLI记录不能替代该验证。现有CPU混合int8与RKNN浮点数据只保留为部署方案补充比较，受控主基线尚未完成。

## 四、资源为主的指标

| 关注项 | 首版记录方式 |
| --- | --- |
| 内存 | 进程树PSS为主、RSS为辅；MiB及相对本机实际MemTotal的比例，注明采样间隔与进程范围 |
| CPU | 窗口CPU核秒、平均占用核数、占整机CPU容量比例；单核百分比与整机容量百分比分开 |
| 资源余量 | Swap、主机最低可用内存；注明这是受实验和其他后台进程共同影响的主机事实 |
| 计算速度 | 计算RTF，固定计算范围、音频分母和追加静音处理；主动回放等待不混进计算RTF |
| 等待 | 加载/首请求，以及实时首个partial和最终结果时间；参考时刻及来源必填 |
| 基本质量 | 有可靠参考的用例报告CER和整句一致性，保留原文及文本归一版本；无参考标未评估 |
| 完整性 | 超时、错误、空结果、EOF残留/强制完成等独立记录；进程正常退出不等于质量或性能合格 |

CPU平均核数≈窗口核秒/窗口墙钟；整机容量占比≈平均核数/本机逻辑CPU数。该占比是被测进程树占整机容量，不是所有进程合计的CPU利用率。

资源分别按**加载、常驻待机、推理中**划分窗口。建议预热后固定约3秒短待机窗口，再测推理；保存可对齐的阶段起止时刻，避免全case平均掩盖驻留与活跃开销。采样峰值不是内核高水位。

NPU忙碌率、独占内存及功耗仅在存在可靠可读接口时作为可选指标。没有读数就记未测；NPU频率不当利用率，进程PSS不当NPU独占内存。

没有人工末音标签时，等待明确命名为相对能量锚点或相对文件边界，不报告人工末音延迟或正式误切分率。保留分段原文供查看。标注不是首版执行前置条件。

## 五、结果数据与静态展示

数据流：协议/用例/候选配置 → 执行适配器 → 原始事件及资源 → 校验与汇总 → 结构化结果 → 静态HTML。

结构化结果需携带：格式/协议/指标版本、设备与部署身份、用例及参考来源、比较类型/组、执行强度、运行轮次、阶段时间、指标单位/范围/样本数、失败与缺失原因，以及原始证据链接。结果格式与JSON schema见[结果数据契约](result-format.md)。

执行完成、输出完整性、质量是否评估和性能目标是否满足分别表示；未知不填零。重复轮次不增加独立语料数量，小样本优先显示逐条结果和范围，不据此宣称长期稳定p95。

Dashboard首先展示CPU、PSS内存占比、RTF和实时等待；质量与参考可信度并列可见。单模块/共跑、非实时/实时、不同协议及两类对照分组展示，满足条件时才比较。不生成跨模型任务、跨口径的总分榜。

页面仅读取结构化结果并生成静态文件；更换页面模板不改变测量数值，不重新推理。

## 六、历史数据与交付

原始报告、配置、日志、hash及测量源码保持不变。转换只映射有可靠证据的字段，记录legacy来源和转换规则；无法确认的阶段窗口、分母、标签等保留未测或不可比。关键选型缺口才补测，不全量重跑。

候选结果按适用条件解释：优先当前需求下的资源和性能，在有限质量证据范围内给推荐；无质量证据时给性能候选和缺口，不给已完成质量选型的结论。
