# YOLOv6 · 640×352、30fps 目标实测

2026-10-21（Asia/Shanghai）。设备 RK3566 / Orange Pi 3B / 4GB；driver0.9.6。

**本轮实际 ROS 检测节点单独运行和两轮 ASR NPU 共跑均完成全部目标帧，约30fps；ASR计算变慢。** 默认配置已经固定为上游缩放后的640×352 RGB、30fps。

FPS按完成检测数除以输入窗口或最后完成时间计算，排除加载与三帧预热。`status=ok`表示实验执行完成；CPU候选虽然程序正常退出，仍明显达不到30fps。p95仅为这轮样本分位数，CPU样本少，不能当作长期稳定p95。

ROS案例复用实际检测节点、DDS消息、容量二的双阶段队列、绘图和检测发布；发布者与检测节点组合在同一进程，未启用rclcpp intra-process优化。标注案例额外订阅RGB图，不包含JPEG或web编码。上游逐帧缩放在进入检测器前完成，本次未计入该阶段。

串行核心probe偶发跳过过时帧，实际ROS队列可缓冲短时抖动，因此核心probe598/600与ROS全部完成并不矛盾。吞吐约30fps也不等于每帧检测消息都在33.33ms内返回。

CPU使用旧PT重导出的浮点ONNX候选，输出布局匹配，后处理与NPU同源；尚未证明模型权重与现用RKNN严格同源，**不报告严格硬件加速倍数**。当前生产CPU备用后端是Haar，不是本次CPU YOLO候选。

## 与ASR共跑的影响

| ASR方案 | 单独逐请求RTF | 共跑充分重叠请求RTF | 重叠均值 |
| --- | --- | --- | ---: |
| NPU，第1轮 | 0.30 / 0.31 / 0.29 / 0.30 | 0.58 / 0.50 / 0.49 / 0.49 | 0.515 |
| NPU，第2轮 | 0.30 / 0.31 / 0.29 / 0.30 | 0.49 / 0.49 / 0.50 / 0.50 | 0.495 |
| CPU2线程 | 0.29 / 0.29 | 0.39 / 0.40 | 0.395 |

RTF越低越快。NPU充分重叠请求均值从约0.30升至0.515/0.495，即计算时间增加约72%/65%；两轮YOLO均900/900。识别这段固定录音的NPU文本一致，但不构成准确率数据集。

ASR使用官方native CLI连续文件解码，约10秒的同一WAV，每次追加0.8秒尾静音并重新加载模型。它是活跃吞吐压力，不是常驻模型的真实麦克风流式交互；没有测首个partial、真人末音延迟或整车并发。充分重叠定义为请求墙钟区间至少95%位于视觉窗口内；区间包括ASR加载，不等同于每时刻都在执行NPU kernel。两轮ASR第5次请求只有部分重叠，第6次在视觉结束后；不把这些较快尾段混入重叠均值。CLI计时仅保留其打印精度。

ASR CPU为旧混合int8 ONNX部署，NPU为RKNN浮点部署，精度不同；本表也不作为同精度硬件竞速。CPU ASR共跑同样完成900/900，但使用两条CPU线程；当前结果不足以把其效果归因于单一硬件资源。两条NPU任务共享资源的同时还涉及CPU后处理与系统调度，本轮未分离各项贡献。

## 参数与配置

- 默认输入固定640×352、30fps，不通过降帧率判定达标。模型编译输入同为640×352。
- YOLO置信度0.30、NMS0.30；可配置但会改变检测结果。当前目标成绩使用默认阈值。
- CPU ORT测1/2/4线程，4线程在已测候选中最快，仍约1.95fps。NPU不把CPU线程数或多核开关当成RK3566算力倍增参数。
- 视觉使用系统runtime1.4.0，ASR独立进程使用私有2.2.0；未替换系统库、内核或机器人配置。
- 标注订阅可配置。当前代码无订阅也绘图，订阅后额外复制/发布RGB图。

复测入口：[yolo.json](../../../tools/edge_benchmark/yolo.json)、[ASR CPU同口径对照](../../../tools/edge_benchmark/yolo-scheduling.json)。

## 内存与测量边界

PSS为整个进程树的系统内存，**不是NPU专用内存**；RKNN设备分配可能不完全计入，不能据此宣称NPU总内存只占该数值。资源文件保留MemAvailable、swap、CPU核秒、温度和CPU/NPU频率。NPU使用原有动态调频设置，目标主矩阵采样为600MHz，未进行锁频或超频测试。

图像解码和上游缩放在正式窗口之前完成；只证明该输入契约下检测模块的表现。未运行相机采集、MJPEG解码、tracking、整车业务或web视频消费者，没有机器人动作。固定图像不能替代不同场景的检测准确率、运动效果和长时间压力验证。

## 失败和历史诊断

- 原ONNX只有LFS指针，下载恢复未成功；新CPU候选的导出命令、版本、hash见preparation清单。
- 系统OpenCV4.2 DNN缺少ReduceMax层，转用独立ORT环境；系统numpy路径覆盖虚拟环境及ROS typesupport路径缺失也已定位并绕行。原始失败日志在[diagnostics](diagnostics/)。
- 视觉runtime2.2.0尝试在core-mask初始化返回-13，未进入模型推理；不能据此认定该模型本身不能用2.2.0。正式共跑保留独立运行库。
- 旧1280×720、无节奏吞吐和10Hz案例仅作[输入诊断](diagnostics/input-matrix/report.html)，不用于30fps目标结论。旧准备过程有并行编译/安装的探索数据仍在外置yolo-01，未混入目标成绩。
